# penny

penny is a Chrome extension (always written lowercase) that tells shoppers on Amazon product pages whether to **Buy now** or **Wait**, based on a price-drop forecast from the Python backend in `app/`.

## Loading the extension (development)

1. Open `chrome://extensions` in Chrome.
2. Turn on **Developer mode** (toggle in the top-right corner).
3. Click **Load unpacked** and select the `extension/` folder (the one containing `manifest.json`).
4. Pin it from the puzzle-piece Extensions menu so its icon stays in the toolbar.
5. Click the icon to open the side panel on the right. It stays open as you switch tabs and follows whichever tab is active. Resize it by dragging its left edge.

### Reloading after changes

- **`manifest.json` or anything in `content/` changed:** click the reload (↻) icon on the extension's card in `chrome://extensions`, then **refresh any open Amazon tabs**. Already-open pages keep running the old content script until they're refreshed.
- **Side panel files changed (`sidepanel/*`):** close and reopen the side panel (or right-click inside it and choose **Reload**).
- **`background/` or `shared/` changed:** click reload (↻) on the extension's card. The background worker only picks up changes after a reload.

If something fails to load, Chrome shows an **Errors** button on the extension's card with the details.

## How the extension is organized

```
extension/
  manifest.json            Extension config; lists the content scripts in load order
  shared/                  Loaded by both the side panel and the background worker
    config.js              API_BASE_URL and the request timeout
    storage.js             chrome.storage wrapper (localStorage fallback for previews)
    dates.js               Local-date helpers, upcoming holidays (Halloween, Black Friday, Christmas, New Year)
    watchlist.js           Watch records: create, save, update, remove
  background/
    background.js          Service worker: alarm, price checks, notifications
  icons/                   Coin icon: penny.svg / penny-small.svg sources, exported PNGs, export-icons.sh
  fonts/                   Inter (variable, Latin) with its OFL license file
  content/                 Runs inside amazon.com pages
    utils.js               parsePrice, detectCurrency, cleanText
    extractors/generic.js  schema.org Product reader (JSON-LD, microdata, meta tags)
    extractors/amazon.js   Amazon extractor (ASIN, title, price strategies)
    content.js             Picks an extractor by hostname, answers the side panel
  sidepanel/               The side panel (opened from the toolbar icon)
    sidepanel.html         Markup for every state (all styling in sidepanel.css)
    api.js                 Data layer: getDetection(), getPreferences(), getPrediction()
    render.js              Rendering layer: fills in the markup
    theme.js               Picks the seasonal and coin color blends (colors live in sidepanel.css)
    sliders.js             Deadline (1–90 days) and savings sliders, holiday badge, saved in chrome.storage.sync
    watchlist-ui.js        The context button, the watch list, simulate buttons
    sidepanel.js           Controller: follows the active tab, dev tools
  mock/                    Fake /predict responses
  screenshots/             Design review screenshots (regenerated by hand; not used by the extension)
```

Flow: when the side panel opens, `sidepanel.js` calls `getDetection()`. That sends `{ type: "GET_PRODUCT" }` to the active tab's content script, which runs the extractor and replies with `{ status, product }`. If the status is `"ok"`, `getPrediction(product, preferences)` POSTs the product and the slider values to the backend, and `render.js` draws the card. When a slider moves, `sliders.js` waits 300 ms, then `sidepanel.js` sends a new request and cancels any request still in flight, so only the latest result is shown.

The panel stays open across tabs, so `sidepanel.js` re-runs detection and the forecast when:

- **You switch tabs** (`chrome.tabs.onActivated`), or the active tab starts loading a new page (`chrome.tabs.onUpdated`, status `"loading"`). The card is cleared and rebuilt.
- **The page finishes loading** (status `"complete"`), or the content script reports it's ready or that Amazon changed the URL in place, e.g. picking another color (`PAGE_CHANGED`). This refresh is quiet: if it's still the same product at the same price, the card is left alone.

Each run is numbered, and starting a new one cancels the previous run's forecast request, so a slow answer for a tab you've left can never replace the current one. "Buy now" scrolls the page to Amazon's own Buy Now / Add to Cart button.

"Wait & watch" saves a watch in `chrome.storage.local`. Every 30 minutes, `background.js` checks each watch's price and shows a notification when the target price is hit, or when the deadline is 3 days away and the price hasn't dropped.

To add a store (e.g. Target), write `content/extractors/target.js`, add it and the store's URL pattern to `manifest.json`, and register it in the `EXTRACTORS` list in `content/content.js`.

## Connecting to the backend

The side panel calls `POST http://127.0.0.1:8000/predict` with `{ ...product, preferences }`. The request comes from the side panel, not the content script, and the request and response shapes are defined in `app/schemas.py`.

- **Backend URL:** `API_BASE_URL` in `shared/config.js`. If you change it, also update `host_permissions` in `manifest.json`, or Chrome will block the request.
- **Preferences:** `getPreferences()` in `sidepanel/api.js` sends `min_savings_pct` (1–30 from the slider; the backend allows 1–50), `deadline_days` (1–90), and `min_confidence_pct` (50–95, the schema's limits) from the confidence slider. If storage is empty or broken, the sliders default to 5%, 14 days and 65% (the backend's own default for `min_confidence_pct`).
- **Response extras:** `predicted_low_usd` and `best_day` appear as "predicted lowest price: $X on DATE" ("today" when that's today). The expected drop (`expected_drop_pct` / `expected_drop_usd`) appears in "why?" only on a wait card; on buy now it would sit next to the predicted lowest price and look contradictory.
- **Data source:** for `"simulated"`, `"mixed"` and `"mock"`, a note under the chance line says what the estimate is based on, so nothing implies real price history when there isn't any. `"real"` shows no note.
- **Real price history (`history_status`):**
  - `"ready"`: no note.
  - `"fetching"`: the backend answered from labeled simulated history and is fetching real history in the background. The panel shows that forecast with "loading real price history…". Every 30 seconds it polls the cheap `GET /history-status/{product_id}`, at most 4 times (`HISTORY_RETRY` in `sidepanel/sidepanel.js`), and re-requests `/predict` only once the status changes from `"fetching"`. After the limit, it says it couldn't load real history yet. A backend without that endpoint (a 404) falls back to re-requesting `/predict`. Switching tabs or products, or closing the panel, cancels polling. A slider move cancels a pending poll, and its own answer starts polling again if needed.
  - `"failed"` / `"unavailable"`: the result stays, with the data-source note.
  - Older backends that don't send the field are treated as `"ready"`.
- **Current price for watches:** `getCurrentPrice(watch)` in `background/background.js` calls `GET /price/{product_id}` and expects `{ "price": 123.45 }`. That endpoint doesn't exist yet; until it does, checks are skipped quietly (and so are price-drop notifications from real checks).
- **Errors:** requests time out after 10 seconds. The panel shows separate messages for a backend that isn't running, a timeout, a 422 (with the backend's own message, e.g. "Only USD prices are supported right now."), and any other failure, with a **Try again** button.

Start the backend from the repo root before opening the side panel:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Each `/predict` call for a new product adds labeled simulated history to `data/processed/price_history.json`, so expect that file to change while testing.

## Testing states with dev tools

Unpacked installs show a **Dev tools** section at the bottom of the side panel with three dropdowns:

- **Product:** use the real current tab ("Live"), or fake a detection result: product found, price not found, item unavailable, not a product page, unsupported site, or detection error.
- **Data source:** **Backend** (default) calls `/predict`; **Mock** skips the backend and uses the mock file below.
- **Mock file:** pick a file from `mock/` (`predict.json`, `predict_wait.json`, `predict_buy_now.json`, `predict_low_confidence.json`, `predict_not_enough_data.json`, `predict_fetching.json`, `predict_unavailable.json`), "fetching, then real history on retry", a request that never finishes (loading state), or one that fails (error state). Every mock matches `PredictResponse` in `app/schemas.py`.

Below the dropdowns, **Watched item** with **Simulate price drop** and **Simulate deadline approaching** runs the background worker's real notification code with a faked price or date. Simulating resets the item's "already notified" flags, so you can repeat the demo.

The dropdown choices are saved in `chrome.storage.local` and kept between panel openings. Dev tools start collapsed, and are hidden automatically for Chrome Web Store installs.

To demo a wait verdict, use the confidence slider. AirPods Pro 2 (`B0BDHWDR12`) with a 3% savings goal and a 35-day deadline is "buy now" at 65% (a 59% chance) and "wait" at 50%.

**Demo mode** (checkbox at the top of Dev tools) hides the dev tools completely, for judging, and is remembered. Any mock settings you picked stay in effect. To bring the dev tools back, press **Alt+Shift+D** (Option+Shift+D on a Mac) with the panel focused, or click the coin 5 times.

Debugging logs:

- **Content script:** open DevTools on the Amazon tab. The Console shows `penny detection: <status>` with the full result.
- **Side panel:** right-click inside the panel and choose **Inspect**.
- **Background worker:** on `chrome://extensions`, click **service worker** on the extension's card.

### Notifications on macOS

Chrome needs permission to show notifications: **System Settings → Notifications → Google Chrome → Allow notifications**. In **Banners** style, the notification buttons ("Buy now", "Keep waiting") are hidden under **Options**; choose **Alerts** to show them directly. Focus modes and Do Not Disturb hide notifications too.

## Design

The side panel follows the design in `student_shopping_assistant_chrome_extension_side_panel.html` (the 360×800 panel only), rebuilt as plain CSS with no remote scripts or fonts. Top to bottom:

1. **Product line:** small, the title and the current price.
2. **Verdict card:** the verdict in extra-bold Inter with **why?** right next to it, the penny coin on the right (hover the card to toss it), and "predicted lowest price: $5.69 on nov 10" underneath (from `predicted_low_usd` and `best_day`, or "… today"). **why?** expands, inside the same card, the backend's explanation, the typical drop (wait cards only) and "forecast reliability: …" from the backend's `confidence`.
   - "wait" or "buy now" sits on one line, large. A leaning verdict shows "leaning" large, with the verdict words smaller and stacked beside it; the stack is exactly as tall as "leaning", and a single word ("wait") is centered in it.
   - Every case is the same height, so nothing below moves. The verdict and coin scale down a little on narrow panels so the verdict, "why?" and the coin never overlap.
   - A short fade plays when the verdict changes, except with reduced motion. "wait" uses the text color, "buy now" emerald, and any leaning verdict grey.
3. **Data-source note:** whenever the estimate isn't all real price history. For simulated data: "real price history isn't available for this item. this estimate uses simulated prices, not real price history." For mixed: "only part of this item's price history is real. this estimate is partly based on simulated prices." While real history loads, it says so first.
4. **Chance line:** from the backend's `p_drop`, the savings %, the dollar amount at today's price and the real date, e.g. "90% chance you'll save $0.06+ (1%) by nov 13."
5. **Sliders card:**
   - "when do you want it by?", with its value ("by nov 13") right-aligned on the label's line. Any day from 1 to 90; the value adds "· black friday", "· halloween", "· christmas" or "· new year's day" within 2 days of that holiday, for any year.
   - "how much do you want to save?", with its value ("$0.06 · 1%") right-aligned on the label's line. 1% to 30%, on a copper → silver → gold track.
   - "how sure do you want to be?", sent as `min_confidence_pct` (default 65). The schema only accepts 50–95, so the slider runs from 50 to 95. Its value ("65% · medium") is right-aligned on the label's line, like the other two, with "50%" and "95%" under the slider. The words come from `CONFIDENCE_LEVELS` in `sidepanel/sliders.js`: up to 64 low, up to 79 medium, then high.
   - On narrow panels the labels wrap; the value pills shrink slightly but never wrap.
6. **One button:** "wait & watch" saves a watch, then reads "watching" (click again to stop) or "update watch" if the sliders have changed. When the verdict is buy now, it reads "buy now at $X": it scrolls the page to Amazon's own buy button and closes the side panel.
7. **Watch confirmation:** "add to google calendar: we'll tell you if it drops 1% before nov 13." The link opens Google Calendar's event-template page in a new tab (no sign-in or API), pre-filled with:
   - title: "last day to buy: [short title] — check penny";
   - an all-day event on the watch's deadline;
   - a description with the target, the product URL and the starting price. All values come from the saved watch and are URL-encoded.

   **see watched items** appears once, at the bottom above the brand mark, on every page. It opens the watched items, each with its target, deadline and **remove**; **close** hides them.
8. **Dev tools:** collapsed, and hidden entirely in Demo mode.
9. **Brand mark:** "penny" at the very bottom, one small bronze circle per letter, colored like the coin, built in HTML/CSS (screen readers hear "penny").

All text is lowercase (CSS `text-transform`), including product titles and the backend's explanation. Everything uses Inter, bundled in `extension/fonts/` with its SIL Open Font License file. The hierarchy comes from weight and size: the verdict is 800, slider labels 600, and body text 400.

The deadline's season sets the whole panel: three slowly drifting blurred blobs behind frosted glass cards (nearly solid cards where `backdrop-filter` isn't supported), blending smoothly between neighboring seasons. December is a dark, high-contrast theme. That switch is deliberately discrete rather than blended, because a half-dark background would leave text on mid-gray. The product line and chance line sit on soft glass plates too, so they stay readable over any blob. With **prefers-reduced-motion**, the blobs don't drift, the coin doesn't toss, and colors switch without fading.

The coin rests tilted about 30°, so both its face ("p", in Inter bold) and its edge show. Five stacked rim discs give it visible thickness. The "p" is nudged up slightly, because its descender makes it look low when it's exactly centered. Adjust that with `--coin-letter-offset` on `.coin-stage` in `sidepanel.css` (default `-0.07em`; more negative raises it).

The brand mark's letter case is set in a single rule, `text-transform` on `.brand-mark` in `sidepanel.css`; change it to `uppercase` for "PENNY". Its colors are `--brand-key-*`, which point at the coin's colors, so the mark is bronze in every season.

### Where the colors live

Every color is a custom property in the "Colors" section of `extension/sidepanel/sidepanel.css`:

- **Text, glass, slider tags and tracks (including the confidence track, `--confidence-track-*`):** the first `:root` block (light) and `:root[data-theme="dark"]` (December).
- **Verdict:** `--verdict-wait`, `--verdict-buy`, `--verdict-leaning` (separate values for dark).
- **Button:** `--button-watch-*`, `--button-watching-*`, `--button-buy-*`.
- **Seasons:** `--season-<name>-1/-2/-3` (the three blobs; `-1` also fills the date slider) and `--season-<name>-base` (light background) for `early-fall`, `halloween`, `november`, `winter`, `christmas`, `new-year`, `late-winter`, `late-winter-pink`, `spring` and `summer`. The dark background is `--mesh-dark-base`.
- **Savings track:** `--coin-track-start`, `--coin-copper-*`, `--coin-silver-*`, `--coin-gold-*`.
- **Coin:** `--coin-face*`, `--coin-rim-*`, `--coin-letter`.
- **Brand mark:** `--brand-key-border`, `--brand-key-text`, `--brand-key-background`.
- **Price bar:** `--range-*`.
- **Mesh and glass:** `--mesh-blob-opacity`, `--mesh-blur`, `--glass-background*`, `--glass-blur`.
- **Fade speed:** `--color-transition-duration`.

*When* each palette applies is set in `extension/sidepanel/theme.js`: the anchor dates (`SEASON_ANCHORS`), the 0/15/30% coin stops (`COIN_STOPS`), and which months are dark (`isDarkSeason`).

If you make the blobs much stronger or the glass more transparent, recheck contrast. With the current values, the worst case over a full-strength blob (New Year) is muted text at 5.7:1, body text at 8.8:1, the grey verdict at 4.6:1 and the emerald verdict at 4.4:1. The verdict is large text, which needs 3:1.

### Icons

`extension/icons/penny.svg` is the coin used at 32, 48 and 128px (and for notifications). `penny-small.svg` is a simplified version for the 16px toolbar icon. After editing either one, re-export the PNGs with headless Chrome:

```bash
sh extension/icons/export-icons.sh
```
